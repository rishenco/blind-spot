# Контроль пространства и оценка паса — при неточном убеждении

*Дата обращения ко всем ссылкам — 2026-08-25.*

## Задача

Боту нужны две числовые оценки:
1. **Куда встать** без мяча — так, чтобы контролировать полезное пространство и оставаться
   невидимым.
2. **Куда пасовать / бросать** — оценка коридора и точки перехвата.

Спортивная аналитика решает ровно это, но при **точно известных** позициях всех 22 игроков.
Главный вопрос ресерча — что происходит с этими моделями, когда позиции соперников заданы
распределением. Ответ короткий: **модели переживают это лучше, чем ожидаешь**, потому что почти
все они уже устроены как «вероятность контроля», а не как «булев контроль», и подстановка
распределения даёт корректное матожидание. Разбор ниже.

---

## 1. Voronoi / dominant region — почему не берём

Простейшая модель: каждая точка поля принадлежит ближайшему игроку → диаграмма Вороного.
Критика (обзор в Wu & Swartz, §2, см. ниже): игнорируются скорости, ускорения и сам мяч.

Taki & Hasegawa (1996, 2000) ввели «dominant region» — область, куда игрок доберётся раньше
всех **с учётом его текущей скорости и ускорения**; границы уже не прямые, а кривые.

**Не берём Вороного**, потому что у нас поле пустое, игроков четверо, и ускорение огромное
(18 м/с², выход на vmax за 0.31 с) — то есть геометрия зон определяется почти исключительно
расстоянием и текущей скоростью. Вороной без скоростей выродится в «кто ближе», а это мы и так
знаем. Dominant region по времени прибытия — берём, но в форме §2.

## 2. Время прибытия с ограничением по ускорению — рабочая формула

Wu & Swartz, «A New Metric for Pitch Control based on an Intuitive Motion Model»
([PDF, SFU](https://www.sfu.ca/~tswartz/papers/pitch_control.pdf), скачан и прочитан целиком,
2026-08-25).

Модель: игрок с начальной позицией (x₀, y₀) и скоростью (vx₀, vy₀) выбирает вектор ускорения
(aₓ, a_y) с |a| = a, разгоняется до vmax, дальше идёт равномерно. t* — момент выхода на vmax,
решение уравнения

```
|v₀ + a·t*| = vmax      →      квадратное уравнение относительно t*
```

Положение:

```
x(t) = x₀ + vx₀·t + ½·aₓ·t²                                  , t < t*
x(t) = x₀ + vx₀·t* + ½·aₓ·t*² + (t − t*)·(vx₀ + aₓ·t*)       , t ≥ t*
```

(и аналогично по y). Алгоритм: перебрать направления (aₓ, a_y) по окружности, для каждого
решить t(x) и t(y), принять те, где они совпадают, взять минимум.

**Валидация, которую стоит знать:** на выборке 5887 пасов команда, определённая как
контролирующая точку, оказывалась фактическим получателем паса **в 91 % случаев**.

### Что из этого берём мы

Перебор направлений ускорения — избыточен для наших чисел. Проверим: время выхода на vmax
= 5.5/18 = 0.306 с, путь за это время 0.84 м. Типичные дистанции в решениях бота — 3–12 м, то
есть 0.5–2.2 с. Значит фаза разгона — 10–30 % длительности и почти не влияет на **направление**.

Поэтому берём упрощение Spearman/Shaw (§3):

```
T(p → q) = t_react + |q − (p + v_p · t_react)| / vmax
```

с `t_react ≈ vmax / a = 0.31 с`. Это не эвристика — в реализации Laurie Shaw именно так и
прокомментировано: «Roughly determined as vmax/amax». Ошибка относительно точной модели —
доли десятых секунды, и она систематическая (одинаковая для всех), то есть в сравнениях
сокращается.

**Важно для нас**: `t_react` здесь склеивает два разных понятия — физический разгон (0.31 с) и
когнитивную задержку (для человека 200–300 мс). Для бота их надо держать раздельно: физика
одинакова у всех, а `reactionLatency` — ручка сложности.

## 3. Pitch control по Spearman: вероятность контроля, а не булева зона

W. Spearman, «Beyond Expected Goals», MIT Sloan Sports Analytics Conference 2018.
Официальный PDF на sloansportsconference.com **у меня не открылся** (отдаёт HTML). Формулы
привожу по открытой референсной реализации Laurie Shaw:
[Friends-of-Tracking / LaurieOnTracking, `Metrica_PitchControl.py`](https://github.com/Friends-of-Tracking-Data-FoTD/LaurieOnTracking),
лицензия MIT, файл скачан и прочитан построчно 2026-08-25.

**Шаг 1. Вероятность, что игрок i успел к точке к моменту T** — сигмоида вокруг его времени
прибытия τ_i:

```
f_i(T) = 1 / ( 1 + exp( −π/(√3·σ_tti) · (T − τ_i) ) )
```

`σ_tti` — разброс времени прибытия. У Shaw `tti_sigma = 0.45 с`. Коэффициент π/√3 — это
пересчёт стандартного отклонения логистического распределения в его масштабный параметр
(логистика с масштабом s имеет σ = πs/√3).

**Шаг 2. Накопление контроля.** Интегрируется ОДУ по времени T:

```
dPPCF_i/dT = ( 1 − Σ_j PPCF_j(T) ) · f_i(T) · λ_i
```

Смысл: «мяч ещё никем не контролируется» × «игрок i уже добежал» × «скорость взятия контроля».
У Shaw `λ_att = λ_def = 4.3` 1/с (в статье вратарь получает ×3, и есть коэффициент κ_def = 1.72,
дающий защите преимущество; Shaw ставит κ = 1 для симметрии).

Численно: шаг dT = 0.04 с, отсечка игроков с `τ_i − τ_min > time_to_control`, интегрирование до
сходимости.

**Почему эта форма — подарок для нашей задачи.** Она уже вероятностная и уже монотонна по
времени прибытия. Значит подстановка **распределения** позиции соперника даёт корректный
результат простой заменой:

```
PPCF_def(q) при неточном убеждении  =  Σ_c b(c) · PPCF_def(q | соперник в c)
```

то есть просто взвешивание по сетке убеждения. Но так делать дорого. Дешёвая и почти
эквивалентная замена, которую я рекомендую:

```
τ_def(q) = min по c с весом:  τ(c → q), взятая как НИЖНИЙ перцентиль
           распределения времён прибытия по сетке b
```

Например 10-й перцентиль: «есть 10 % шанс, что соперник добежит быстрее, чем за столько».
Это превращает неопределённость в один скаляр и даёт естественную ручку риска: осторожный бот
берёт 5-й перцентиль, наглый — 50-й. Ручка `decisionQuality` может управлять именно этим.

**Проверка на вырождение (обязательная).** Когда убеждение размазано по всему полю, нижний
перцентиль τ_def становится маленьким **везде**, и бот решает, что пасовать некуда, — паралич.
Лечение: смешивать с матожиданием, `τ = (1−ρ)·E[τ] + ρ·q₁₀[τ]`, ρ ∈ [0, 1] — ещё одна честная
ручка «осторожность».

## 4. Перенос на наше поле: что конкретно считать

Наши отличия от футбола: 4 игрока вместо 22, поле 24×14 вместо 105×68, дуга вратаря R = 4 м
как запретная зона, стены, от которых мяч отскакивает, мяч слышен всегда.

### 4.1 Карта угрозы (для позиционирования без мяча)

Сетка та же, что у убеждения (48×28, 0.5 м). Для каждой ячейки q:

```
threat(q) = P(гол | мяч оказался в q у соперника)
```

Дешёвая форма без обучения: убывающая функция расстояния до наших ворот и угла обзора ворот из
q, с обнулением внутри дуги R = 4 м (оттуда бросок не засчитывается):

```
threat(q) = 0                                   если q внутри дуги вратаря
threat(q) = w_ang · (angle(q → створ) / π)
          · w_dist · exp( −(|q − goal| − 4) / L )   иначе
```

`angle(q → створ)` — угловой размер 3-метрового створа из точки q; L ≈ 6 м. Это аналог того, что
в футбольной аналитике называется shot value / xG-поверхностью, только выписанный руками. Учить
не на чем и не надо.

Ценность позиции защитника:

```
V_def(p) = Σ_q threat(q) · b_carrier(q_reach) · P(я успею в q раньше носителя)
```

на практике — свёртка карты угрозы с «моей зоной досягаемости», где зона считается по §2.

### 4.2 Оценка паса

Пас параметризуется (направление, скорость релиза 12–22 м/с). Оценка:

```
score(pass) = P(напарник поймает) · V(состояние после приёма)
            − P(перехват соперником) · V(состояние после потери)
            − cost_noise(релиз 18 м + полёт мяча)
```

`P(перехват)` считается по формуле §3 вдоль траектории мяча: для каждого момента T траектории
берём точку мяча m(T) и сравниваем τ_def(m(T)) (по убеждению, с перцентилем) c T.

**Специфика, которой нет в футболе: ловля — это тайминг, а не автомат.** `P(напарник поймает)`
зависит от того, знает ли напарник о пасе. Событие «релиз» слышно на 18 м = всё поле, значит
напарник его услышит; но направление он не знает. Значит вероятность приёма зависит от того,
насколько напарник уже двигался в нужную сторону. Для бота-напарника это решается общей
командной моделью (см. `decision-architectures.md` §6). Для паса **человеку** — это принципиально
хуже, и бот должен это учитывать понижающим коэффициентом.

**Специфика: стены.** Мяч отскакивает и звучит на отскоке (20 м). Значит существует пас в стену
— и он должен быть в списке кандидатов, потому что: (а) траектория ломаная, перехват сложнее;
(б) отскок — громкое событие, то есть это ещё и инструмент дезинформации. Расчёт перехвата
вдоль ломаной делается тем же перебором по времени (§5 `interception.md`).

### 4.3 Значение скрытности как член полезности

Ни одна модель из спортивной аналитики этого не содержит — там всех видно всегда. Добавляем сами:

```
U(action) = V_position(action)            // из §4.1/4.2
          − κ · ΔH_mirror(action)         // насколько действие сузило зеркальное убеждение
          + μ · H_mirror_current          // ценность быть уже неизвестным
```

`H_mirror` — мера «размазанности» зеркальной сетки (§5 `belief-tracking.md`): энтропия, или
проще и читаемее — **эффективная площадь** (площадь ячеек, покрывающих 80 % массы). Площадь в
м² лучше энтропии, потому что её можно нарисовать в оверлее и назвать вслух: «соперник знает
меня с точностью до 30 м²».

Именно этот член заставляет «стоять молча» иногда выигрывать, без хардкода. И именно κ и μ —
самые интересные для тюнинга числа во всём боте.

## 5. Чего в спортивной аналитике нет и брать нечего

- **Expected Possession Value / EPV** (сеточная модель ценности владения, обучается на данных).
  У нас нет данных и не будет. Наша `threat(q)` — это выписанный руками EPV-суррогат, и этого
  достаточно.
- **Off-Ball Scoring Opportunity (OBSO)** — надстройка над pitch control из той же статьи
  Spearman. Смысла добавлять нет при 2 атакующих.
- Всё, что связано с офсайдом, формациями 11 игроков, усталостью.

## Что берём / что не берём

**Берём:**
- Время прибытия `T = t_react + |q − (p + v·t_react)| / vmax`, `t_react_физ = vmax/a = 0.31 с`.
  Раздельно — `reactionLatency` как ручка.
- Сигмоиду вероятности прибытия `f(T) = 1/(1 + exp(−π/(√3σ)(T − τ)))` с σ ≈ 0.3–0.45 с и ОДУ
  накопления контроля с λ ≈ 4–5 1/с. Формулы проверены по коду (MIT), не по пересказу.
- Способ подставить убеждение: **перцентиль времени прибытия** вместо матожидания, с явной
  ручкой осторожности ρ. Плюс обязательный тест на паралич при размазанном убеждении.
- Карту угрозы как свёрнутую вручную функцию (угол створа × расстояние × маска дуги вратаря).
- Член полезности «эффективная площадь зеркального убеждения в м²» — как измеримую скрытность.
- Пас в стену как отдельный класс кандидатов.

**Не берём:**
- Диаграммы Вороного и dominant region в чистом виде.
- Полный перебор направлений ускорения из Wu & Swartz: при a = 18 м/с² фаза разгона слишком
  коротка, чтобы окупить перебор.
- EPV/OBSO и любые обучаемые поверхности ценности.
- Взвешивание PPCF по всей сетке убеждения (Σ_c b(c)·PPCF) как основной путь — дорого; держим
  как эталон для проверки, что перцентильное приближение не врёт.

**Не нашёл:**
- Открытого PDF статьи Spearman 2018 (sloansportsconference.com отдаёт HTML, researchgate —
  тоже). Формулы восстановлены по MIT-реализации Laurie Shaw, где они закомментированы с
  прямыми ссылками на уравнения статьи («see Eq 4 in Spearman, 2018»). Значения κ_def = 1.72 и
  λ = 4.3 взяты из комментариев в этом коде, а не из статьи напрямую.
- Работ по pitch control при **неопределённых** позициях. Похоже, их просто нет: в трекинге
  позиции известны. Перцентильный подход из §3 — моё предложение, а не литература.
