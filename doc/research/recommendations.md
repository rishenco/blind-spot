## 0. Резюме в шести строках

- **Убеждение о сопернике — сетка занятости** 48 × 28 (ячейка 0.5 м), обновляется на 10 Гц.
- **Убеждение о мяче и о напарнике — калман** (постоянная скорость), обновляется по наблюдениям.
- **Дополнительно — «зеркальная» сетка**: что соперник знает обо мне. Без неё игра не заиграет.
- **Решения — utility AI**: генераторы кандидатов → forward-предсказание на 1 с → взвешенная
  оценка по осям → argmax с гистерезисом. 10 Гц.
- **Никакого MCTS, никакого GOAP/HTN, никакого BT как основы.**
- Всё это стоит ~2 % кадрового бюджета на двух ботов. Узкое место — не производительность, а
  детерминизм и дисциплина «слой 2 не видит мир».

## 1. Архитектура убеждения

### 1.1 Что чем представлять

| Объект | Представление | Обоснование |
|---|---|---|
| Соперник ×2 | **сетка занятости 48×28, ячейка 0.5 м**, Float32Array | мультимодальность, стены, дуга вратаря, негативная информация — всё это одна структура. `belief-tracking.md` §1.3 |
| Мяч | **KF, постоянная скорость**, + отдельный `predictBall(t)` с отскоками | наблюдается непрерывно, унимодален. `interception.md` §1.2 |
| Напарник | **KF** при `teamShare > 0`; сетка при `teamShare = 0` | как в B-Human: свои шлют себя сами |
| Я в глазах соперника ×2 | **грубая сетка 24×14, ячейка 1 м** | `belief-tracking.md` §5 |

Итого 4 сетки соперников/зеркал на бота, 8 на двух ботов, 43 КБ. Не проблема.

### 1.2 Цикл обновления сетки соперника (10 Гц)

```
1. ПРЕДСКАЗАНИЕ — смесь режимов движения, а не изотропная диффузия:
     b ← w_stand·b
       + w_walk ·blur(b, 2.5·dt)
       + w_run  ·blur(b, 5.5·dt) · P(бег отсюда НЕ был бы услышан)
   Ядро при dt=0.1 и 0.5 м/ячейку — трёхточечное [α, 1−2α, α]. Смещать центр ядра,
   если есть свежая оценка направления движения трека.

2. МАСКА — обнулить стены и дугу вратаря R=4 м; ренормализовать.

3. ПОЛ — b ← max(b, ε) на проходимых ячейках, чтобы потерянный соперник переоткрывался.

4. НЕГАТИВ ОТ ТИШИНЫ — уже учтён множителем в шаге 1. Это главный источник
   интересной формы облака: рядом со мной оно растёт медленно, вдали быстро.
```

Позитивные наблюдения обрабатываются **по событию**, не по тику:

```
b(c) ← b(c) · exp( −dist²(c, z) / (2σ²) );   ренормализовать
```

при анизотропной σ (см. §1.4) — гауссиана в полярных координатах вокруг слушателя.

Негатив от пинга — **отложенно**, с учётом волнового фронта:
для ячейки на расстоянии d апдейт применяется в момент `t_ping + d / waveSpeed`:

```
b(c) ← b(c) · (1 − p_detect(c)),   p_detect ≤ 0.95, зона сжата на ~1 м от честной
```

Никогда не обнулять. Обоснование трёх правил (сжатая зона, p<1, умножение) —
`belief-tracking.md` §3.

### 1.3 Ассоциация анонимных событий

```
для события z:
  1. ГЕЙТ по достижимости (librcsc): трек k допустим, если
       dist(z, mode(b_k)) ≤ vmax·age_k + 3.5·σ(d) + slack
  2. Если допустим ровно один трек — обновить его (жёстко).
  3. Иначе — PDA: λ_k = Σ_c b_k(c)·L(z|c);  w_k = λ_k / Σλ;
       b_k ← normalize( w_k·[b_k·L] + (1−w_k)·b_k )
  4. ЭКСКЛЮЗИВНОСТЬ: если событие однозначно принадлежит треку k,
       применить к остальным трекам негативный апдейт по зоне вокруг z.
```

Отдельно и обязательно: **пинг, вернувший меньше хитов, чем есть соперников**, даёт негативный
апдейт по всем непокрытым трекам. Это самое информативное наблюдение в игре.

### 1.4 Две правки к модели восприятия (обе важные, обе за пределами брифа)

**(а) Шум локализации — коррелированный во времени, а не белый.**

```
bias ← bias·exp(−dt/τ) + N(0, σ(d)·√(1−exp(−2dt/τ))),   τ ≈ 0.5–1.0 с
observed = truth + bias
```

Иначе бот, фильтруя непрерывно звучащий мяч при 60 Гц, получает точность в ~5 раз лучше
человеческой при `truthLeak = 0`. Разбор с числами — `interception.md` §5.

**(б) Шум локализации — анизотропный.** Направление слышно хорошо, дистанция плохо:

```
σ_tangential ≈ 0.05·d      (≈ 3°)
σ_radial     ≈ 0.20·d
```

Правдоподобнее, и превращает триангуляцию между напарниками в настоящую механику.
`audio-games.md` §2.

Обе правки касаются **симуляции**, а не бота, и должны применяться к человеку тоже. Это вопрос
к геймдизайну, но без них слой 1 будет калиброван неверно.

## 2. Архитектура решений

### 2.1 Конвейер

```
belief ──► ПРИЗНАКИ ──► ГЕНЕРАТОРЫ (30–60 кандидатов) ──► FORWARD 1 с ──► ОСИ ──► argmax
                                                                                   │
                                       гистерезис (bonus + min hold 0.3 с) ◄───────┘
                                                                                   │
                                                     исполнение: КА + steering 60 Гц
```

**Признаки** (все считаются только из belief, никогда из мира):
`threatMap(q)`, `τ_self(q)`, `τ_opp(q)` (перцентиль по сетке), `interceptTable`,
`H_mirror` (эффективная площадь зеркального облака в м²), `age(b_k)`, `P(перехват паса)`.

**Оси полезности** (см. `decision-architectures.md` §2.2):
`u_goal`, `u_intercept`, `u_exposure`, `u_stealth_value`, `u_info`, `u_deception`, `u_team`,
`u_commit`. Комбинация — геометрическое среднее (или makeUpValue), не голое произведение.

**Три оси из восьми (`u_exposure`, `u_stealth_value`, `u_deception`) требуют зеркального
убеждения.** Если его не сделать, придётся хардкодить «стой молча» и «делай финт», и бот
мгновенно станет нечитаемым и нетюнингуемым. Это главный вывод всего ресерча.

### 2.2 Учёт неопределённости

Режим B — **перцентили** (по умолчанию): все времена прибытия соперника берутся как q-й
перцентиль распределения по сетке, q ≈ 10–25 (ручка осторожности).
Режим C — **детерминированные стратифицированные сэмплы** (K = 5–8) + агрегация по нижнему
квантилю. За флагом, включать только если турнир покажет провал в бимодальных ситуациях.

Обязательный тест режима B: при размазанном убеждении бот не должен впадать в паралич
(«везде опасно, пасовать некуда»). Лечение — смешивание перцентиля с матожиданием.

### 2.3 Частоты и бюджет

| Слой | Частота |
|---|---|
| Физика, приём событий, steering | 60 Гц, фиксированный шаг |
| Убеждение (диффузия, негатив) | 10 Гц |
| Позитивный апдейт | по событию |
| Решение | 10 Гц + немедленно на «важное» событие |

Оценка: убеждение ~1.5 млн оп/с на 8 сеток, решения ~20 тыс. оп на бота на решение.
Ориентир из RoboCup: agent2d укладывается в 500 оценок предсказанного состояния за такт 100 мс.
Мы на порядок ниже. `belief-tracking.md` §4, `decision-architectures.md` §5.

### 2.4 Командность

Роли (`Носитель` / `Тень`) назначаются **детерминированной функцией от общего состояния**, без
переговоров — как в RoboCup. Владение мячом известно всем всегда (мяч звучит).

`teamShare` реализуется как **обмен событиями**, не сетками: на два порядка дешевле, слияние не
нужно, оба бота прогоняют один детерминированный эстиматор и сходятся. Плюс это точный аналог
войс-чата у людей.

## 3. Порядок реализации (по убыванию отдачи)

**Веха 1 — каркас честности.** `BeliefState` как единственный вход слоя 2 (физически: у
`Decision` нет ссылки на `World`, только на `Belief`). Шина событий. Оверлей убеждения (сетка,
тепловая карта, возраст в секундах). Двойной вид. Детерминизм, seeded RNG.
*Без оверлея всё остальное неотлаживаемо — он должен появиться первым, а не последним.*

**Веха 2 — слой 1 базовый.** Сетка, диффузия смесью режимов, позитивные апдейты, гейт +
PDA-ассоциация. Калман на мяч. Тест: сценарий «соперник ходит по известному маршруту» —
сравнить максимум сетки с правдой, построить график ошибки от времени молчания.

**Веха 3 — негативная информация.** Пинг (с волновым фронтом), эксклюзивность, негатив от
тишины. Тест: «соперник стоит молча в углу, бот пингует из центра» — убеждение не должно
навсегда вычеркнуть угол.

**Веха 4 — слой 2 базовый.** Признаки, генераторы, оси 1, 2, 7, 8. Бот, который умеет
перехватывать, пасовать и бить. Ещё не умеет прятаться.

**Веха 5 — зеркальное убеждение и оси 3, 4, 6.** Здесь появляется собственно игра: тишина,
финты, ложный пинг. Тест: сценарии обманываемости из критерия успеха №1.

**Веха 6 — ручки и турнир.** Все ручки в конфиг, батч-прогоны, графики «ручка → сила».

Ключевая мысль про порядок: **веха 5 — это не полировка, это суть.** Если ресурс кончится
раньше, лучше иметь слабого, но прячущегося бота, чем сильного, но всегда бегущего.

## 4. Альтернативы, если основная не полетит

### Альтернатива A: частичный фильтр вместо сетки

Если сетка окажется слишком грубой (например, если поле или число игроков вырастет, или если
понадобится хранить скорость в состоянии) — заменить на частичный фильтр, 200–500 частиц на
трек, систематический ресэмплинг с seeded RNG, sensor resetting при вырождении.

Что при этом теряется: детерминизм становится хрупче, негативная информация от пинга (который
покрывает почти всё поле) вызывает вырождение популяции, а признаки требуют кластеризации
частиц. Что приобретается: скорость в состоянии и непрерывность.

**Триггер перехода:** если выяснится, что решения бота систематически ошибаются из-за отсутствия
скорости в убеждении, и что подсказка направления (`belief-tracking.md` §2.5, вариант 2) этого
не решает.

### Альтернатива B: короткий rollout вместо utility

Если взвешенная сумма осей окажется невозможной для настройки (типичный симптом: тюнинг одной
оси ломает три сценария из пяти) — заменить оценку на **rollout**: проиграть каждого кандидата
вперёд на 2–3 с против простой скриптованной модели соперника, взять исход. Это ближе к
action chain из agent2d, но с честной моделью противника.

Что при этом теряется: читаемость «почему выбрано» (оценка перестаёт раскладываться на
понятные оси — а это требование к оверлею). Что приобретается: не нужно вручную балансировать
восемь чисел.

Компромисс, который я бы попробовал первым: **оставить оси, но откалибровать их веса
автоматически** прогонами (grid search по весам на наборе сценариев). Это не ML — это
подгонка десятка констант перебором, и она полностью детерминирована.

### Альтернатива C (аварийная): дозированный truthLeak

Если гипотеза человека провалится — то есть если окажется, что честный бот при любых настройках
скучен, — прежде чем включать `truthLeak`, попробовать в таком порядке:
1. поднять `decisionQuality` (глубина, K, число кандидатов);
2. включить `teamShare = 1` и идеальную координацию;
3. **и только потом** — минимальный `truthLeak`, привязанный к состоянию осведомлённости, как
   в Thief («свободное знание, масштабируемое по состоянию ИИ»), а не глобально.

Мой прогноз: до пункта 3 не дойдёт. Обоснование — `difficulty-and-honesty.md` §2: наша игра
структурно лучше подходит для честной сложности, чем шутеры, потому что деградация информации
здесь **видна игроку**, а деградация исполнения — нет.

## 5. Риски

| Риск | Вероятность | Последствие | Смягчение |
|---|---|---|---|
| Слой 2 подглядывает в мир (случайно, через общий объект) | высокая | вся работа обесценена, и это не заметно на глаз | архитектурно: `Decision` конструируется только с `Belief`; линтер/тест, запрещающий импорт `World` в файлы слоя 2 |
| Бот всегда движется, «стоять молча» никогда не выигрывает | высокая | главная механика игры мертва | оси 3/4 + метрика «доля времени тени в тишине» в отчёте каждого турнира |
| Мигание решений на границе двух вариантов | высокая | читается как «тупой бот» | гистерезис двумя механизмами (веха 4, не позже) |
| Негативная информация вычёркивает правильную область навсегда | средняя | бот уверенно ищет не там, выглядит сломанным | p_detect < 1, сжатая зона, пол ε; тест из вехи 3 |
| Бот ловит мяч лучше человека за счёт фильтрации | средняя | нечестность, которую никто не заметит и не спишет на ручки | коррелированный шум (§1.4а) + ручка `observationMemory` |
| Недетерминизм через порядок обхода коллекций | средняя | невоспроизводимые баги, невозможно сравнить версии | только массивы в местах, влияющих на выбор; тест «два прогона одного сида дают побайтово равные логи» |
| Тюнинг восьми весов вырождается в бесконечный цикл | средняя | сроки | сценарный набор с числами (критерий №1) до начала тюнинга; при провале — альтернатива B |
| Пинг R=14 покрывает всё поле 24×14, убеждение всегда либо точное, либо пустое | **уже так** | пространство «интересных ошибок» схлопывается | это вопрос к геймдизайну, не к боту, см. `belief-tracking.md` §6 |

## 6. Что я бы поднял на обсуждение с человеком до начала кода

Три вещи, которые вылезли из ресерча и относятся к дизайну, а не к ИИ:

1. **Пинг R = 14 м на поле 24 × 14 м покрывает всё поле** (от центра до угла 13.89 м). Сонар —
   не «room-read», а полный снимок. `belief-tracking.md` §6.
2. **Таблица громкости почти бинарна**: радиусы 12/14/18/20/30/40 м при полудиагонали поля
   13.9 м означают «слышно везде». Реально локальны только шаг шагом (4 м) и ловля (6 м).
   Для сравнения: в RoboCup 2D дальность командной связи намеренно ≈ половина поля.
3. **Модель ошибки локализации** должна стать коррелированной во времени и анизотропной, иначе
   (а) бот честно получает нечестное преимущество на ловле, (б) триангуляция между напарниками
   не работает как механика.

Ни одно из трёх не блокирует начало работы над ботом — архитектура из §1–2 от них не зависит.
Но все три меняют то, насколько интересным получится результат.
