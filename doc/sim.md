# Симуляция и контракт восприятия

*Написано для агента, который будет писать ИИ поверх этого. Код и комментарии — по-английски,
этот документ — по-русски. Числа тюнинга живут в `src/sim/config.ts`, а не здесь: если в доке
и в конфиге расходятся цифры, прав конфиг.*

## Что где лежит

| Файл | Что это |
|---|---|
| `src/sim/types.ts` | весь словарь: мир, звук, восприятие, `Intent`, `Controller` |
| `src/sim/config.ts` | **все** тюнинг-числа, пресеты, `scaleLoudness`/`resizeField` |
| `src/sim/sim.ts` | физика и правила. Ничего не знает о рендере, DOM и потребителях |
| `src/sim/perception.ts` | `Perceiver` — единственный мост из мира в решения |
| `src/sim/match.ts` | сборка: симуляция + перцепторы + контроллеры + статистика + таймлайн |
| `src/sim/replay.ts` | запись = сид + конфиг + имена контроллеров + внешние интенты |
| `src/sim/controllers/` | дамми-стратегии и `scripted` (сценарии-таймлайны) |
| `src/sim/ai/` | бот: убеждение, признаки, полезности (`doc/ai/architecture.md`) |
| `src/sim/cli/batch.ts` | headless-турнир и совместный свип поля/громкостей |
| `src/sim/cli/contest.ts` | **турнир правил**: три теста концепта по каждому набору контактных механик |
| `src/sim-ui/` | дебаг-полигон (canvas 2D), `handball.html` |
| `tools/handball-shots.mjs` | генератор ключевых кадров с фотометрическими проверками |

## Главная гарантия

Контроллер получает **только** `PerceptionFrame` и `ControllerContext` (свой id, команда,
геометрия поля, конфиг, свой seeded RNG). Ссылки на `Simulation`, `WorldState` или свой
`Perceiver` у него нет и появиться не может: `Match` конструирует контроллеры сам и передаёт им
кадры. Во фрейме нет ни одного объекта, общего с миром, — все векторы копируются.

Практический тест этого: правый вид полигона рисуется функцией `drawPerceived(ctx, cam, model)`,
у которой в области видимости нет мира вообще. Если бы контракт протекал, кадр был бы другим.

## Поток данных за тик

```
Controller.decide(dt) -> Intent          (по кадру, полученному в конце ПРЕДЫДУЩЕГО тика)
Simulation.step(intents) -> { events, touches, sonar, goals, turnovers }
Perceiver.hear(world, events)            -> шум, анонимизация, задержка
[teamShare] Perceiver.relay(наблюдения напарника)
Perceiver.receiveSonar(свои возвраты)
Perceiver.frame(world, field) -> PerceptionFrame -> Controller.onPerceive(frame)
```

Реакция бота минимум на тик «опаздывает» — ровно как у человека. `reactionLatencySec`
добавляется поверх.

## Что во фрейме

```ts
PerceptionFrame {
  self: SelfState          // проприоцепция: своя позиция, скорость, прицел, заряд броска,
                           // кулдаун пинга, ownLoudness (радиус, на котором меня сейчас слышно),
                           // down/reaching, stealPressure, carrySeconds, lastCatchFail
  match: { t, tick, phase, score, timeLeft }   // свисток слышат все
  field: FieldInfo         // поле не секрет
  hearing: Record<SoundKind, number>   // НА КАКОМ РАДИУСЕ я услышал БЫ каждый вид звука
  events: ObservedEvent[]  // только новые с прошлого кадра
  emitters: ObservedEmitter[]          // непрерывные источники (мяч)
  sonar: SonarReturn[]     // возвраты своего пинга, приходят по мере движения фронта
  teammates, opponents: EntityId[]
}
```

### `ObservedEvent` — дискретный звук

- `pos` — с ошибкой; `sigma` (вдоль луча) и `sigmaBearing` (поперёк) + `bearing` (единичный
  вектор наблюдатель→звук). **Ошибка анизотропна**: направление слышно хорошо, дистанция плохо.
  Облако — «сигара» вдоль луча. Пересечение двух сигар от напарников — настоящая триангуляция.
- `sourceId` — `null` для чужих (кроме случаев `anonymousSources=false`). Свои, свои напарники
  и мяч — именованы. Ассоциация анонимных событий с треками — твоя задача.
- `intensity` — громкость события в метрах слышимости (та же шкала, что в таблице концепта).
- `self`, `relayed` — своё; пришло по войсу от напарника (`teamShare`).
- Пинг и свисток приходят **точно** (`perception.exactKinds`) — это цена вопроса.

### `ObservedEmitter` — мяч

Мяч не сыплет метками: он даёт **постоянную оценку позиции** с той же анизотропной ошибкой.
Ошибка **коррелирована во времени** (`emitterNoiseSmoothing`, по умолчанию 0.97/тик ≈ 0.5 с):
независимый шум на 60 Гц позволял бы усреднить десятки замеров и знать мяч точнее человека.
Это проверено тестом (`perception.test.ts`, «keeps a listening bot from averaging…»). Ручка
`ai.observationMemory` зарезервирована для тебя: сколько замеров боту вообще позволено копить.

### `SonarReturn` — и негативная информация

Пинг — это **едущий фронт** (`ping.waveSpeed`, 42 м/с; `Infinity` = мгновенный снимок; кадры
обоих вариантов сняты, выбор за человеком). Каждый тик, пока фронт жив, приходит возврат:

```ts
SonarReturn { pingId, t, origin, range, waveRadius, sweptFrom, sweptTo, aim, coneCos, hits, complete }
```

`hits` — что нашли (`wall | crease | player | ball`; чужие — без `sourceId` и без скорости).
`sweptFrom..sweptTo` + `aim`/`coneCos` — **какой объём честно проверен на этом тике**: кольцевой
сектор. Всё, что внутри него и не в `hits`, — гарантированно пусто. Возврат приходит и тогда,
когда не найдено ничего: пустая проверка — это сообщение, а не молчание.

Второй источник негативной информации — `frame.hearing`: если в кадре нет `step-run`, значит в
радиусе `hearing['step-run']` (9 м по умолчанию) никто не бежал.

## Контракт контроллера

```ts
interface Controller {
  readonly name: string;
  reset?(ctx: ControllerContext): void;
  onPerceive?(frame: PerceptionFrame): void;   // сюда обновление убеждения
  decide(dt: number): Intent;                  // сюда политика
  debugSnapshot?(): ControllerDebug | null;    // сюда всё, что хочешь видеть на экране
}

interface Intent {
  move: Vec2; moveMode: 'walk' | 'run';   // длина move > 1 обрезается, 0 = стоять
  aim: Vec2;                              // 0 = оставить прежний
  ping: boolean; charge: boolean; catch: boolean; dive: boolean;
}
```

`ping`, `catch`, `dive` читаются по фронту нажатия; `charge` — удержание, бросок происходит в
момент отпускания. Длительность замаха читай из `frame.self.chargeT`, а не из своего таймера:
свисток, фамбл или розыгрыш могут оборвать замах без твоего ведома (дамми на этом уже
спотыкались, см. отчёт).

`ControllerDebug` рисуется полигоном как есть: `label`, `readouts`, `markers` (точка/линия/круг),
`scores` (топ вариантов) и **`beliefs: BeliefCloud[]`** — облака взвешенных точек с возрастом и
уверенностью. У `BeliefCloud` есть необязательные `cell` (рисовать квадратами реального размера
ячейки, а не точками) и `color`. Бот кладёт туда сетки соперников и зеркальные сетки; выпадашка
**belief overlay** в полигоне выбирает, какой слой рисовать.

Регистрируй свой контроллер в `src/sim/controllers/index.ts` — и он сразу доступен полигону
(выпадашка), батч-раннеру (`--a mybot`) и сценариям кадров.

### Что `SelfState` рассказывает о себе (добавлено вместе с борьбой за мяч)

| Поле | Смысл |
|---|---|
| `down` | лежу после подката: не двигаюсь, ничего не могу, и падение все слышали |
| `reaching` | руки открыты (нажата ловля и окно не истекло) |
| `stealPressure` | 0..1, насколько соперник уже дожал отбор у **меня** |
| `carrySeconds` | сколько держу мяч — часы пассивности, изнутри |
| `lastCatchFail` | `early` / `late` / `past` и время: почему сорвалась последняя попытка |

Всё это — **проприоцепция**, не разведка: это про собственное тело и ничего не говорит о том,
где кто находится. `stealPressure` обязателен по геймплею: отбор без предупреждения — не борьба,
а лотерея, и ни убежать, ни отпасовать заранее нельзя.

## Ловля: окно, а не тест на дистанцию

Одно нажатие открывает руки на `catching.reachSec` (0.22 с), затем `reachCooldownSec` (0.35 с)
до следующего. Мяч, оказавшийся за это время в `catching.radius` (1.6 м), пойман. Удержание
кнопки не работает — читается фронт нажатия.

Старое правило («нажать в окне ±`windowSec` от момента наибольшего сближения») арифметически не
существовало: мяч на 16 м/с проходит 1.2 м за 150 мс, то есть окно ±180 мс шире всего пролёта,
а поздняя половина окна недостижима — тело встречает мяч (0.47 м) раньше, чем наступает
наибольшее сближение. Теперь обе половины реальны и **различимы**, и обе публикуются в
`SelfState.lastCatchFail`. Пинится тестом `makes both halves of the catch timing reachable`.

## Борьба за мяч (`config.contest`)

Появилась вместе с отменой решения «контакта в v1 нет». Каждая механика — отдельный
выключатель, потому что турнир правил (`npm run contest`) обязан уметь мерить их по одной.

| Блок | Что делает | Ключи |
|---|---|---|
| `steal` | продержался в `radius` (1 м) от носителя `holdSec` (1 с) — забрал мяч, и это слышно на 9 м | `enabled` `radius` `holdSec` `requirePress` `minSpeed` `knockLoose` `graceSec` |
| `tackle` | подкат: попал — соперник лежит `stunSec` и роняет мяч; промахнулся — лежишь сам | `enabled` `radius` `stunSec` `missPenalty` `dropsBall` |
| `collision` | тела не проходят друг сквозь друга; удар быстрее 4.5 м/с слышен и сбивает темп. `dropsBall` по умолчанию **выключен**: с ним получалось 16 фамблов в минуту | `enabled` `restitution` `loudSpeed` `staggerSec` `dropsBall` |
| `block` | `'always'` = старое правило (тело на линии — стена), `'speed'` = быстрый бросок с шансом проходит мимо | `mode` `speedSpan` `minStop` `activeAlwaysStops` |

Новые события контакта приходят из `step()` в `StepOutput.contests` (`steal | tackle |
tackle-miss | collision | block | through`). Поле необязательное — те два места, что собирают
пустой `StepOutput` руками, не пришлось трогать.

**Две новые строки в `SoundKind`**: `steal` (9 м — мяч сменил руки) и `ball-near` (3.5 м —
мяч прошёл мимо тела, которое его не поймало). Обе существуют по одной причине: наказание,
которого не слышно, неотличимо от бага. Мяч, бесшумно прошедший сквозь игрока, который только
что нажал ловлю, — это ровно та непрозрачность, которая закрывает игру на джеме за минуту.

Остальные контактные события переиспользуют существующие строки таблицы, и это тоже решение:
удар телом и падение от подката звучат как `brake` (11 м), выбитый мяч — как `fumble` (14 м).
Побочный эффект приятный — слой убеждения ассоциирует их с треками соперников без единой
новой строчки.

`player.bodyCollision` / `player.bodyRestitution` **удалены** — переехали в
`contest.collision.enabled` / `.restitution`.

`player.brakeTurnCos` наконец читается: резкая смена направления на бегу теперь звучит
(`brake`, 11 м). К нему добавились `brakeTurnMinSpeed` (ниже неё поворот беззвучен — иначе
тихий приход в позицию перестал бы быть тихим) и `brakeTurnWindowSec` (0.5 с: разворот на 90°
при 5.5 м/с и 18 м/с² занимает 0.43 с, в окно 0.2 с он не влезает и звучал бы как ничего).

## Ручки честности (`config.perception`)

| Ручка | По умолчанию | Смысл |
|---|---|---|
| `hearingScale` | 1 | множитель ко всем радиусам слышимости |
| `localizationSigmaPerMeter` / `Cap` | 0.06 / 1.5 | ошибка **по дистанции** |
| `localizationBearingDeg` | 1.5° | ошибка **по направлению** (малый угол, без тригонометрии) |
| `anonymousSources` | true | различает ли слушатель чужих «по голосу» |
| `reactionLatencySec` | 0 | задержка доставки события |
| `truthLeak` | 0 | подмешивание правды в **локализацию услышанного**, 0 = честно, 1 = точно |
| `xrayHz` | 0 | сколько раз в секунду наблюдателю **просто говорят**, где все тела. Настоящая телепатия |
| `teamShare` | false | напарники делятся услышанным (уже зашумлённым, `relayed: true`) |
| `emitterNoiseSmoothing` | 0.97 | корреляция ошибки по мячу во времени |
| `exactKinds` | sonar, whistle | что слышно без ошибки |

`truthLeak` — не телепатия, и это важно для интерпретации замеров: он убирает ошибку
локализации у звуков, которые наблюдатель **и так услышал**, и потому ничего не может сделать
с тем, чем в этой игре в основном прячутся, — со стоянием молча. Измерено: `truthLeak = 1` сам
по себе не даёт почти никакого преимущества. Чтобы вопрос «стоит ли информация хоть чего-то»
вообще можно было задать, добавлена честная читерская ручка `xrayHz`: наблюдателю раз в 1/hz
секунды подсовывается синтетический возврат сонара, накрывающий всё поле, — с точными позициями
всех тел и с негативной половиной («больше нигде никого нет»). Канал выбран не случайно: это
единственный канал контракта, который уже несёт обе половины знания, поэтому потребителю не
нужен ни один особый случай. Разница между честным ботом и телепатом обязана быть во входе,
никогда — в коде.

### Восприятие по командам (`config.perceptionByTeam`)

`config.perception` — один объект на матч, то есть ручка крутится сразу обеим сторонам. Для
теста «телепат обыгрывает честного» этого недостаточно по построению. Добавлено необязательное
поле `perceptionByTeam: (Partial<PerceptionConfig> | null)[]`, индекс — id команды; функция
`perceptionFor(cfg, team)` кладёт оверрайды поверх глобальных. `Perceiver` резолвит их один раз
в конструкторе, `Match` спрашивает про `teamShare` для каждой команды отдельно.

`config.ai` — мешок ручек бота (`beliefCell`, `beliefHz`, `decisionQuality`, `observationMemory`,
веса полезности…); симуляция его не читает, но он ездит вместе с конфигом в реплеях и в батче.
Список ключей — в `doc/ai/architecture.md` и в комментарии к `AiConfig`.

## Детерминизм

Шаг фиксирован (1/60), `Math.random()` запрещён (проверяется тестом), настенных часов в
симуляции нет. В физике и восприятии нет тригонометрии и `Math.exp`: они не бит-в-бит
переносимы между движками. Потоки RNG разделены: у симуляции свой, у каждого наблюдателя свой,
у каждого контроллера свой — добавление наблюдателя или бота не сдвигает физику (тест есть).

`Simulation.hash()` хеширует биты всего состояния. Реплей — это **переигрывание**: сид + конфиг +
имена контроллеров + внешние интенты. Скраб таймлайна пересимулирует матч с нуля (10 800 тиков ≈
0.5 с) и заново прогоняет восприятие — то есть «что слышал P2 в момент гола» отвечает настоящий
конвейер, а не кэш картинок.

## Как запускать

```
make up                 # полигон в браузере (dev-сервер в докере)
npm test                # детерминизм + правила + контракт восприятия + бот (41 тест)
npm run batch -- --a bot --b striker --seeds 1-50
npm run batch -- --a striker --b goalie --seeds 1-10 --sweep 24x14@1,20x12@0.8
npm run deception       # сценарии обманываемости бота, числами
npm run honesty         # дыра с мячом + шкала сложности по ручкам честности
npm run tune            # grid search по весам полезности бота
npm run shots:handball  # ключевые кадры -> out/handball/
npm run contest         # турнир правил: три теста концепта по каждому набору механик
npm run contest -- --only steal,all --seeds 1-16 --secs 90
```

`npm run contest` разгоняется по `os.cpus()` процессам (`fork` самого себя, `CONTEST_WORKER=1`):
матч бота против бота идёт ~2 500 тиков/с в одном процессе, а турнир — это тысячи матчей.

Бот и его слои описаны в `doc/ai/architecture.md`.
