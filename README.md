# BLIND HANDBALL (prototype)

Слепой гандбол 2×2. Концепт и законы — ниже по ссылкам.
Концепт — `doc/concept.md`, порядок работы — `doc/process.md`.

## Запуск

Нужны только **Docker** (с `docker compose`, то есть Docker Desktop или Docker Engine 20.10+)
и **make**. Node на машине не нужен — он живёт в контейнере.

```sh
make up
```

Поднимает vite dev-сервер в контейнере, ждёт, пока он реально начнёт отвечать, и открывает
http://localhost:5173 в браузере. Если открыть нечем (headless-машина, ssh) — просто печатает URL.

Порт занят? `make up PORT=5180`.

| Цель | Что делает |
|---|---|
| `make up` | собрать образ (если нужно), поднять dev-сервер, дождаться и открыть страницу |
| `make down` | остановить контейнер |
| `make logs` | смотреть вывод vite |
| `make build` | продакшен-сборка (`tsc --noEmit` + vite) в `dist/` |
| `make shots` | перегенерировать ключевые кадры в `out/` (headless chromium внутри контейнера) |
| `make sh` | шелл внутри контейнера |
| `make reset` | снести контейнеры, их volume'ы и собранные образы |

Правки в `src/` подхватываются на лету. Если на macOS/Windows hot reload молчит (события
файловой системы через bind-mount там теряются) — `VITE_POLL=1 make up`, watcher переключится
на polling.

### Как это устроено

`npm ci` выполняется **при сборке образа**, отдельным слоем: сначала копируются только
`package.json` и `package-lock.json`, потом ставятся зависимости, и лишь потом код. Пока
зависимости не менялись, слой берётся из кэша, а старт контейнера — это просто запуск vite.
В рантайме ничего не устанавливается.

Анонимный volume на `/app/node_modules` в compose — не место установки, а щит: он не даёт
bind-mount'у рабочей копии перекрыть то, что уже лежит в образе (докер заполняет пустой
volume содержимым **образа**, а не bind-mount'а). `make up` передаёт `--renew-anon-volumes`,
так что volume пересоздаётся из образа при каждом старте и не может протухнуть.

Образов два, из одного `Dockerfile`:

* стадия `dev` — только node + vite, лёгкая, ей поднимается dev-сервер;
* стадия `shots` — то же плюс playwright и chromium (полгигабайта, поэтому отдельно).
  Chromium ставится **в образ**, а не в volume при первом прогоне.

`make shots` и `make build` запускают контейнер под uid:gid хоста, поэтому `out/` и `dist/`
принадлежат вам, а не root.

## Без Docker

Работает и напрямую, если есть Node 22+:

```sh
npm install
npm run dev      # dev-сервер
npm run build    # dist/
npm run shots    # ключевые кадры в out/ (нужен `npx playwright install chromium`)
```
